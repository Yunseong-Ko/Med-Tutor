# iMedSIS 연계형 학습성과 피드백 레이어

## 한 줄 정의

기존 iMedSIS와 교수 문항뱅크를 대체하지 않고, 시험 후 결과표와 HWP 시험지를 가져와 학생별 약점 분석, 단원별 피드백, 기출 복습 세트로 재구성하는 의과대학 학습성과 피드백 도구.

## 왜 이 방향이 안전한가

- 교수님들이 이미 문항뱅크를 만들고 있다면, 새 문항뱅크를 또 만들겠다는 제안은 중복으로 보일 수 있다.
- iMedSIS는 학사 시스템이므로 직접 DB 연동이나 로그인 기반 크롤링은 초기 과제 범위와 개인정보 측면에서 부담이 크다.
- 하지만 학생/교수자가 이미 내려받는 시험 결과표, HWP 시험지, 이의제기 내역을 입력 자료로 쓰는 것은 현실적이다.
- 핵심 차별점은 "문항 생성"이 아니라 "시험 결과를 학습 가능한 피드백으로 바꾸는 것"이다.

## 권장 MVP 범위

1차 MVP는 iMedSIS 직접 연동이 아니라 `export/import` 방식으로 한다. 다만 결과표 다운로드 가능 여부는 아직 확정하지 않고, CBT 시스템에서 확보 가능한 데이터 수준에 따라 3단계로 나눈다.

### 데이터 확보 시나리오

#### A안: 문항별 결과표 확보 가능

가장 이상적인 시나리오다. 학생 또는 교수자가 시험 후 문항별 O/X 결과, 평균, 표준편차, 본인 점수를 내려받을 수 있다면 이를 업로드해 바로 피드백 리포트를 만든다.

- 구현 난이도: 낮음
- 개인정보 리스크: 익명화 처리 시 낮음
- 데모 설득력: 높음
- 핵심 기능: 문항별 O/X 맵, 단원별 약점 분석, 틀린 문항 복습 세트

#### B안: 문항별 결과는 없고 점수 통계만 확인 가능

학생이 평균, 표준편차, 자기 점수만 볼 수 있고 문항별 O/X를 받을 수 없다면, 개인 피드백보다 교수용 시험 분석 데모로 방향을 조정한다. 문항별 정답률은 교수/행정 담당자가 제공 가능한지 확인해야 한다.

- 구현 난이도: 중간
- 개인정보 리스크: 낮음
- 데모 설득력: 중간
- 핵심 기능: 점수 위치 해석, 과거 시험 대비 변화, 교수 제공 문항 통계 기반 단원 리포트

#### C안: CBT 결과 원자료 접근 불가

CBT 결과를 외부로 내보낼 수 없다면, 1차 MVP는 실제 성적 연동 대신 `기출 복습/자가 CBT`로 전환한다. 학생이 과거 HWP 시험지를 플랫폼에서 풀면, 그 풀이 로그를 기반으로 동일한 피드백 구조를 보여준다.

- 구현 난이도: 낮음
- 개인정보 리스크: 매우 낮음
- 데모 설득력: 중간
- 핵심 기능: 기출 CBT, 문항별 O/X, 단원별 약점 분석, Anki export

이 경우 최종 포지셔닝은 "학교 CBT 결과를 가져오는 시스템"이 아니라 "학교 기출과 문항뱅크를 기반으로 한 학습용 CBT와 피드백 도구"가 된다.

- 입력 1: 학생별 시험 결과표
  - 예: 평균, 표준편차, 본인 점수, 문항별 O/X
  - 예: `1번 2번 3번 ...` / `O X O ...` 형태의 2행 엑셀
  - 단, 실제 다운로드 가능 여부는 금요일 미팅에서 확인 필요
- 입력 2: 시험지 HWP 또는 PDF
  - 문항 본문, 선지, 정답, 해설, 이의제기 결과를 연결할 수 있는 원천 파일
- 입력 3: 교수/조교 라벨링
  - 과목, 단원, 학습목표, 개념, 난이도, 문항 유형, 이미지/자료 유형

## 제안 슬로건

> 문항뱅크의 다음 단계는 생성이 아니라 피드백입니다.

> P:accine은 시험 결과를 단순 점수표에서 단원별 학습 처방으로 바꿉니다.

> 기존 문항뱅크를 살리고, 학생에게는 다음 시험을 준비할 수 있는 복습 경로를 제공합니다.

## 학생 화면 목업 구조

### 1. 내 시험 결과

- 내 점수, 평균, 표준편차
- 석차/백분위는 학교 정책상 제공 가능 여부에 따라 선택
- 이전 시험 대비 변화
- 과목별/분과별 약점 요약

### 2. 문항별 O/X 맵

- 1번부터 마지막 문항까지 O/X 타일로 표시
- 틀린 문항만 보기
- 고난도 문항만 보기
- 전체 정답률 낮은 문항만 보기
- 이의제기 반영 문항 표시

### 3. 약점 단원 리포트

- 단원별 정답률
- 전체 평균 대비 내 약점 단원
- 반복 오답 개념
- 추천 복습 자료
- 관련 기출/유사 문항
- Anki 카드 다운로드

### 4. 기출 복습 모드

- 과거 시험문제를 실제 시험처럼 풀기
- 틀린 문항만 다시 풀기
- 같은 단원 문항 묶어서 풀기
- 이미지/자료해석형 문항만 풀기

## 교수/조교 화면 목업 구조

### 1. 시험 결과 업로드

- iMedSIS에서 내려받은 결과표 업로드
- 시험지 HWP/PDF 업로드
- 시험명, 과목, 학년, 시험일, 회차 입력
- 자동으로 문항 수와 O/X 열 개수 확인

### 2. 문항 라벨링

- 문항 번호별 단원 매핑
- 학습목표 매핑
- 문항 유형 선택
  - 개념형
  - 임상추론형
  - 처치/검사 선택형
  - 이미지/자료해석형
  - 약물/금기/부작용형
  - 법/윤리/의사소통형
- 난이도, 변별도, 정답률 확인

### 3. 수업 피드백 리포트

- 단원별 전체 정답률
- 학생들이 많이 틀린 개념
- 고난도이지만 교육적으로 좋은 문항
- 정답률이 너무 높거나 낮아 재검토가 필요한 문항
- 이의제기 빈도가 높은 문항
- 다음 강의/보강에 반영할 포인트

### 4. 기출 복습 세트 관리

- 공개 가능 문항만 학생용 세트로 전환
- 교수 승인 전에는 학생에게 노출하지 않음
- 이의제기 반영 후 수정본 관리
- 해설, 근거자료, Anki 카드 연결

## HWP 시험지 활용 방법

### 현실적인 접근

- HWP를 바로 완벽 파싱하려고 하지 않는다.
- 1차 MVP에서는 HWP/PDF에서 문항 번호, 본문, 선지, 정답, 해설을 초안 추출한다.
- 문항 분리 실패, 표/이미지 포함 문항, 정답 불명확 문항은 `needs_review=true`로 보낸다.
- 교수/조교가 검토한 뒤에만 문항뱅크 또는 복습 세트로 들어간다.

### 샘플 HWP 파싱 결과

2026년 6월 3일 기준으로 사용자가 제공한 과정시험 HWP 4개를 로컬에서 테스트했다. 원문은 출력하지 않고, 문항 구조만 확인했다.

| 파일 | 파일명 기준 객관식 수 | 추출 문항 수 | 판단 |
|---|---:|---:|---|
| 인간.사회.의료(Ⅱ) 1차 | 105 | 105 | 문항 번호/선지 구조 추출 가능 |
| 인간.사회.의료(Ⅱ) 2차 | 64 | 64 | 문항 번호/선지 구조 추출 가능 |
| 신경 및 특수감각기학 2차 | 142 | 142 | 문항 번호/선지 구조 추출 가능 |
| 정신의학 과정시험 | 133 | 133 | 문항 번호/선지 구조 추출 가능 |

초기 텍스트 기반 파서에서는 정답이 대부분 자동 추출되지 않았지만, HWP 배치 패턴을 반영해 `문항 지문 끝 동그라미 숫자`를 정답 후보로 인식하도록 개선했다. 이후 샘플 4개에서 정답 추출률이 크게 개선되었다. 그래도 HWP 서식/레이아웃에 따라 정답이나 해설이 누락될 수 있으므로 1차 MVP에서는 `문항/선지 구조화 + 정답/해설 자동 추출 + 교수/조교 검수`로 잡고, 후속으로 HWP 서식 인식 또는 PDF 시각 파싱을 붙인다.

### 현재 만든 로컬 추출 도구

`scripts/extract_course_exam_hwp.py`를 추가했다. 이 스크립트는 HWP 시험지를 문항 단위 JSON으로 바꾸고, 사람이 검수하기 쉬운 Markdown 검수본도 함께 만든다. 결과는 git에 올라가지 않는 `data_private/course_exams/` 아래에 저장한다.

- JSON: `data_private/course_exams/extracted/`
- Markdown 검수본: `data_private/course_exams/markdown/`

생성되는 문항 필드는 다음을 포함한다.

- `question_id`, `source_exam`, `source_file`, `exam_date`, `grade`
- `course_id`, `course_name`, `round_label`
- `question_number`, `stem`, `stimulus`, `choices`, `answer`, `explanation`, `raw_text`
- `labels.unit_id`, `labels.learning_objective`, `labels.concept_tags`
- `labels.question_type`, `labels.cognitive_level`, `labels.difficulty`
- `performance.item_accuracy`, `performance.cohort_accuracy`, `performance.discrimination_index`
- `media.has_image_or_data_reference`, `media.media_refs`
- `review_status`, `needs_review`, `review_reasons`

원문 문항과 추출 JSON은 `data_private/`에 저장되므로 git에는 올라가지 않는다.

### 문항 내부 구조 용어

HWP 문항은 다음 구조로 나누어 저장한다.

- `stem`: 문제의 질문부 또는 문항 줄기. 예: "합당한 논거는?"
- `stimulus`: 박스 안 제시자료, 증례, 사례, 표, 그림 설명.
- `choices`: ①~⑤ 선지.
- `answer`: 정답. 화면에는 보이지만 HWP 텍스트 추출에서 누락될 수 있어 검수 대상이다.
- `explanation`: 정답 및 해설 문서에서 추출 가능한 경우 연결한다.

스크린샷처럼 정답이 `③ 답` 또는 문항 지문 끝의 `④` 형태로 보이는 문항은 우선 자동 추출한다. 그래도 텍스트 변환에서 누락될 수 있는 문항은 `answer_not_extracted`로 표시해 교수/조교 검수 큐로 보낸다.

### 2026년 6월 3일 파서 v0.4.0 미디어 추출 결과

HWP 내부 `BinData` 이미지를 추출하고, HWP XML의 `PictureInfo bindata-id`를 이용해 문항 연결 후보를 생성했다.

| 파일 | 이미지 asset | 이미지 연결 문항 |
|---|---:|---:|
| 인간.사회.의료(Ⅱ) 1차 | 5 | 5 |
| 신경 및 특수감각기학 2차 | 59 | 39 |
| 정신의학 과정시험 | 5 | 5 |

이미지는 `data_private/course_exams/media/{source_exam}/` 아래에 저장하고, 문항 JSON에는 `media.media_refs`로 연결한다. 연결 방식은 HWP 본문 흐름 기반 자동 후보이므로 `match_confidence=0.75`, `needs_review=true`로 저장한다.

검수자는 HTML preview 또는 Markdown 검수본에서 문항별 이미지 후보를 확인하고, 실제 문항 제시자료가 맞는지 승인한다.

### 2026년 6월 3일 PDF 파서 v0.1.0 결과

PDF 시험지도 같은 JSON/Markdown/HTML 검수 구조로 변환할 수 있도록 `scripts/extract_course_exam_pdf.py`를 추가했다. 텍스트 추출은 `pdftotext -layout`을 우선 사용하고, 실패하면 PyMuPDF 텍스트 추출로 대체한다.

실제 다운로드 폴더의 과정시험 PDF 1개를 원문 출력 없이 구조만 테스트했다.

| 파일 | 파일명 기준 객관식 수 | 추출 문항 수 | 정답 추출 | 텍스트 제시자료 후보 | 해설 후보 | 이미지 asset | 이미지 연결 문항 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 인간.사회.의료(Ⅱ) 2차 PDF | 64 | 64 | 63 | 21 | 23 | 11 | 9 |

PDF는 HWP보다 텍스트 레이어와 줄바꿈 보존성이 문서마다 달라서 아래처럼 처리한다.

- 텍스트 선택이 가능한 PDF는 문항 번호, 문항 지문, 선지, 정답, 해설을 1차 자동 추출한다.
- 답 동그라미가 문항 줄 끝에 붙는 경우와 별도 줄에 떨어지는 경우를 모두 정답 후보로 처리한다.
- PDF 내부 이미지 block은 `media_assets`로 저장하고, 페이지/본문 흐름 기준으로 문항 연결 후보를 만든다.
- 스캔 PDF 또는 동그라미 숫자 글리프가 깨지는 PDF는 `pdf_text_layer_missing_or_too_short_ocr_required` 또는 `no_questions_extracted` 경고를 남기고 OCR/수동 검수 대상으로 보낸다.

### 문항 변환 상태

- `imported`: 파일에서 가져온 원본
- `parsed`: 문항 단위로 분리됨
- `labeled`: 단원/개념/난이도 라벨링됨
- `reviewed`: 교수/조교 검토 완료
- `released`: 학생 복습 세트로 공개

## iMedSIS와의 관계 설정

### 하지 않는 것

- iMedSIS 로그인 정보를 받아 자동 접속하지 않는다.
- 내부 DB를 직접 긁지 않는다.
- 공식 승인 없이 개인정보가 포함된 원자료를 저장하지 않는다.
- 성적 데이터를 교수/학생 권한 없이 노출하지 않는다.

### 하는 것

- 사용자가 내려받은 결과표를 업로드한다.
- 업로드된 결과표를 문항 단위 학습 피드백으로 바꾼다.
- 향후 학교 승인 시 iMedSIS와 API 또는 SSO 연동 가능성을 열어둔다.
- 초기는 익명화된 샘플 데이터로 데모한다.
- 결과표 다운로드가 불가능하면, 학교 CBT와 유사한 자가 CBT/기출 복습 모드에서 자체 학습 로그를 생성한다.

## 금요일 교수님께 물어볼 질문

1. 시험 후 학생들이 받는 결과표에 문항별 O/X가 실제로 포함되는지 확인한다.
2. 학생 또는 교수자가 결과표를 엑셀/CSV/PDF 형태로 내려받을 수 있는지 확인한다.
3. 학교 CBT 시스템에서 문항별 정답률 또는 오답률이 교수자에게 제공되는지 확인한다.
4. 교수님은 문항별 정답률, 단원별 정답률, 이의제기 현황을 얼마나 쉽게 확인하는지 묻는다.
5. 기존 문항뱅크가 있다면, 문항별 학습목표/단원/난이도 라벨링이 되어 있는지 묻는다.
6. 학생에게 과거 시험문제를 복습 세트로 제공하는 것이 정책적으로 가능한지 묻는다.
7. 6주 MVP에서 익명화된 결과표 1개와 시험지 1개를 받아 리포트 데모를 만드는 것이 가능한지 묻는다.
8. HWP 정답 표시가 텍스트인지, 밑줄/색상/굵게 같은 서식인지 확인한다.

## 교수 문항 제작에 도움이 되는 라벨링 체계

교수자가 새 문항을 만들 때 처음부터 아래 라벨을 붙이도록 하면, 단순 문항뱅크가 아니라 교육성과 분석이 가능한 문항뱅크가 된다.

### 필수 라벨

- 과목
- 시험 회차
- 문항 번호
- 단원
- 학습목표
- 정답
- 문항 유형
- 난이도

### 권장 라벨

- 핵심 개념
- 오답 유발 포인트
- 선지 구성 방식
- 자료 유형
- 이미지/표/그래프 여부
- 예상 소요 시간
- 이의제기 위험도

### 문항 유형 예시

- `knowledge_recall`: 단순 지식 확인형
- `concept_discrimination`: 유사 개념 변별형
- `clinical_reasoning`: 임상추론형
- `image_interpretation`: 이미지/자료해석형
- `ethics_policy`: 의료윤리/보건의료정책/사회적 판단형
- `treatment_selection`: 검사/치료/처치 선택형
- `contraindication_trap`: 금기/예외/함정형

### AI가 먼저 붙이고, 교수자가 고치는 구조

교수자가 모든 라벨을 처음부터 직접 입력하면 부담이 크다. 따라서 AI가 초안을 붙이고, 교수/조교는 수정만 하도록 만든다.

- AI 초안: 과목, 문항 유형, 인지 수준, 이미지 여부, 핵심 키워드
- 교수/조교 검수: 학습목표, 단원, 정답, 난이도, 공개 여부
- 시험 후 자동 업데이트: 문항별 정답률, 단원별 정답률, 이의제기 여부, 변별도

이 구조가 잡히면 교수 문항뱅크는 단순 저장소에서 `학습성과 피드백 DB`로 확장된다.

## 최종 포지셔닝

이 프로젝트는 "문항 생성 AI"가 아니라 "의과대학 시험 데이터의 학습 피드백화"로 포지셔닝한다.

기존 문항뱅크와 iMedSIS는 그대로 두고, 그 사이에 학생과 교수 모두에게 필요한 교육적 해석 레이어를 만든다.
