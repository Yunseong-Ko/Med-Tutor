# P:accine Learning Analytics Master Prompt

작성일: 2026-06-04  
목적: 지금까지 만든 P:accine MVP를 `기출 풀이 + 문항 라벨링 + 학생 취약 영역 분석 + 교수 피드백 리포트` 중심의 의학교육 데이터 플랫폼으로 수렴시키기 위한 기준 문서와 AI 에이전트용 마스터 프롬프트.

---

## 1. 현재까지 진행한 내용

### 제품 방향

P:accine은 처음에는 교수용 AI 문항 생성/검토 플랫폼으로 출발했지만, 현재 더 명확한 방향은 `학교 내부 기출/과정시험 문항을 구조화하고, 학생 풀이 데이터를 축적해, 학생과 교수 모두에게 다시 피드백하는 학습 분석 시스템`이다.

즉, 핵심 차별점은 단순 생성형 AI 문항 생성이 아니라 다음의 폐쇄 루프다.

1. 기존 HWP/PDF 기출문항 구조화
2. 학생 풀이 환경 제공
3. 문항별 정답률, 풀이 시간, 선택지 분포 수집
4. 문항을 5개 이상의 평가 축으로 라벨링
5. 학생 취약 영역 시각화
6. 교수자에게 수업 보강/문항 개선/추가 문항 제작 근거 제공

### 현재 구현된 기능

- 교수 화면: 문항 생성, 문항 검토, 문항 아카이브, 수업 리포트 구조가 존재한다.
- 학생 화면: 과목 라이브러리, 문제 풀이 화면, 개념 노트, 오답/Anki 화면 구조가 존재한다.
- HWP/PDF 기반 과정시험 문항 구조화 방향이 잡혀 있다.
- 문항 풀이 UI는 UWorld/AMBOSS를 벤치마킹하되 PNU/P:accine 톤으로 재구성했다.
- 학생 문제풀이 화면에서 좌측 문항 목록을 열고 닫을 수 있고, 본문이 전체 폭으로 확장된다.
- `핵심 정보`, `출제 포인트`, `검사/자료`, `개념 노트`, `Anki 카드` 탭이 구현되어 있다.
- 해설이 없거나 부족한 경우 `보강 해설 초안`을 표시하는 구조가 들어갔다.
- 문항별 출처, 문항 유형, 개념 연결, Anki 카드 초안의 UI 기반이 생겼다.

### 현재 남은 핵심 과제

- 문항 구조화 정확도 검증
- 이미지/제시자료 매핑 고도화
- 문항 라벨링 taxonomy 확정
- 학생 풀이 이벤트 저장
- 교수 리포트의 실제 데이터 연동
- 학생 개인 피드백 화면의 실제 데이터 연동
- 팀원 6명에게 수작업/검수/라벨링 업무 배분
- 개인정보/시험자료 보안 원칙 정리

## 2. 최종 목표

### 목표 1. 기존 기출문항을 학생들이 스스로 풀 수 있게 만들기

학생은 과목, 시험, 단원, 문항 유형을 선택해 원하는 문제부터 풀 수 있어야 한다. 끝까지 순서대로 푸는 것을 강제하지 않고, 필요한 문항만 선택해 확인할 수 있어야 한다.

저장해야 할 풀이 데이터:

- `student_id_hash`
- `exam_id`
- `question_id`
- `session_id`
- `selected_choice`
- `is_correct`
- `time_spent_ms`
- `opened_at`
- `answered_at`
- `reviewed_explanation`
- `used_hint`
- `exported_anki`
- `device_context`

### 목표 2. 기출문항을 5개 이상의 평가 영역으로 분류하기

교수와 학생이 모두 이해할 수 있는 문항 라벨링 체계가 필요하다. 최소 5개 이상 축으로 문항을 분류해야 한다.

추천 평가 축:

1. 대분과: 신경, 호흡기, 순환기, 소화기, 내분비, 신장, 감염, 정신, 인간사회 의료 등
2. 세부 주제: 뇌혈관질환, 말초신경, 척수, 시각로, 약물치료, 의료윤리 등
3. 평가 항목: 병태생리, 진단, 검사, 치료, 역학, 위험인자, 예후, 법/윤리, 해부, 약리
4. 인지 수준: 단순 암기, 개념 이해, 자료 해석, 임상 추론, 의사결정, 우선순위 판단
5. 문항 형식: 단일정답, 임상 vignette, 제시자료형, 이미지/검사자료형, 옳은 것/틀린 것, 조합형
6. 출처 범위: 과정시험, PMA, 임종평, KMLE 유사, 교수 강의록, 학생 정리본
7. 난이도/변별도: 정답률, 평균 풀이 시간, 선택지 분산, 이의제기 여부, 교수 검토 상태

### 목표 3. 학생 취약 영역을 시각화하기

학생에게는 단순 점수가 아니라 `어떤 영역을 못하는지`가 보여야 한다.

학생 화면에서 보여줄 지표:

- 과목별 정답률
- 세부 주제별 정답률
- 평가 항목별 정답률
- 문항 유형별 정답률
- 평균 풀이 시간
- 빠르게 틀린 문항
- 오래 풀고 틀린 문항
- 반복 오답 개념
- Anki 카드 추천
- 이어 풀 문항 추천

### 목표 4. 교수자가 시험 결과와 문항별 정답률을 교육에 활용하기

교수 화면은 학생 개인 감시가 아니라 수업 개선과 보강 교육에 초점을 둔다.

교수 화면에서 보여줄 지표:

- 시험 전체 평균/표준편차
- 문항별 정답률
- 선택지별 선택 분포
- 세부 주제별 취약도
- 평가 항목별 취약도
- 교수 강의 단원별 취약도
- 예상보다 정답률이 낮은 문항
- 해설/문항 구조 검토 필요 문항
- 보강 수업 추천 주제
- 추가 문제 제작 추천 버튼

## 4. 디벨롭 방향

### 1차 개발 목표: 기출 풀이 환경 안정화

우선 학생이 실제로 기출을 풀고 데이터가 남아야 한다.

필수 기능:

- 시험 세트 선택
- 문항 목록 열기/닫기
- 문항 선택 이동
- 선지 선택
- 정답/오답 표시
- 해설 확인
- 풀이 시간 측정
- 문항별 풀이 이벤트 저장

### 2차 개발 목표: 문항 라벨링 체계 확정

문항이 라벨링되어야 교수 리포트와 학생 취약 영역 분석이 의미를 가진다.

필수 기능:

- 문항별 라벨 편집 화면
- AI 라벨 초안 생성
- 사람 검수 상태 저장
- 라벨 confidence 표시
- 과목별 taxonomy 템플릿 관리

### 3차 개발 목표: 학생 피드백 화면

학생에게 `무엇을 다시 공부해야 하는지` 보여준다.

필수 기능:

- 약한 대분과 TOP 5
- 약한 세부 주제 TOP 10
- 평가 항목별 레이더 차트
- 오래 풀고 틀린 문항 목록
- 빠르게 틀린 문항 목록
- 추천 복습 문항
- Anki export

### 4차 개발 목표: 교수 리포트 화면

교수에게 `이번 수업/시험에서 무엇을 보강해야 하는지` 보여준다.

필수 기능:

- 문항별 정답률/선택지 분포
- 세부 주제별 정답률
- 평가 항목별 정답률
- 취약 개념 기반 보강 수업 제안
- 다음 시험/형성평가 문항 추천
- 문항 자체 문제 가능성 표시

### 5차 개발 목표: 자동화 운영 시스템

팀원이 6명 있으므로 수작업을 데이터 구축 단위로 나누고, AI는 초안/검수/보고 자동화에 집중한다.

자동화 대상:

- 새 HWP/PDF 업로드 감지
- 문항 구조화 초안 생성
- 이미지/제시자료 후보 추출
- 문항 라벨 초안 생성
- 팀원별 검수 CSV 생성
- 검수 결과 병합
- 매일 진행상황 요약
- 교수 미팅용 리포트 초안 생성

## 6. 병목 지점 TOP 10

1. 제품 방향이 `문항 생성`, `학습 PACS`, `법률 교육`, `IRB 보조`, `CPX/OSCE` 등으로 넓어지며 핵심 MVP가 흔들린다.
2. 기출 원문 파일이 HWP/PDF/사진자료/정답지로 나뉘어 있어 구조화 기준이 흔들린다.
3. 문항 라벨 taxonomy가 확정되지 않아 학생 취약 분석과 교수 리포트가 실제 지표로 이어지지 않는다.
4. 학생 풀이 이벤트를 저장하는 DB 구조가 아직 실제 기능으로 연결되지 않았다.
5. 교수 리포트가 목업 상태라 실제 정답률/풀이 시간/선택지 분포와 연결되어 있지 않다.
6. 이미지/제시자료 매핑이 중요하지만 자동 추출, 수동 검수, 저장 구조가 아직 분리되어 있지 않다.
7. 팀원 6명에게 맡길 수 있는 작업 단위가 세부적으로 쪼개져 있지 않다.
8. 문서와 아이디어가 여러 파일에 흩어져 있어 맥락 회복 시간이 길다.
9. 교수 미팅 전마다 현재 상태, 다음 결정, 필요한 피드백을 새로 정리해야 한다.
10. 개인정보, 시험자료, 학생 학습로그 보안 기준이 기능 개발 속도를 따라오지 못할 수 있다.

1. HWP/PDF 문항 구조화 초안 생성
2. 문항별 5축 이상 라벨 초안 생성
3. 이미지/제시자료 후보 추출 및 `question_id` 매핑
4. 학생 풀이 이벤트 자동 저장
5. 문항별 정답률/풀이시간 집계
6. 학생 취약 개념 자동 요약
7. 교수용 보강 수업 추천 리포트 생성
8. 팀원별 검수 작업 CSV/스프레드시트 자동 생성
9. 매일 개발/데이터 구축 진행상황 자동 브리핑
10. 교수 미팅 전 데모 체크리스트와 논의 안건 자동 생성

## 8. 맥미니 기반 자동화 시스템 설계안

맥미니는 항상 켜져 있는 개인 자동화 서버로 둔다.

### 역할

- 매일 새 파일/문서 감지
- HWP/PDF 변환 및 문항 파싱 작업 실행
- SQLite/Postgres 백업
- 학생 풀이 로그 집계
- 팀원 검수 현황 요약
- 매일 아침/저녁 브리핑 생성
- 교수 미팅 전 자동 리포트 생성

### 추천 폴더 구조

```text
PaccineOps/
  inbox/
    exams_raw/
    answer_keys/
    media_raw/
  processed/
    questions_json/
    media_assets/
    labels/
  reports/
    daily/
    professor_meeting/
    team_status/
  private/
    student_events/
    backups/
```

| 주기 | 입력 | 처리 | 출력 |

| 매일 07:00 | Git 상태, docs, DB | 진행 요약 | morning brief markdown |
| 매일 22:00 | 커밋, 생성 파일, 미완료 TODO | 일일 회고/내일 할 일 | evening brief |
| 30분마다 | inbox 새 파일 | 파일명/유형 분류 | ingest queue |

## 12. 개인정보와 보안 주의점

- 원본 기출문항, 정답지, 학생 풀이 로그는 public Git에 올리지 않는다.
- 학생 데이터는 `student_id_hash`로 저장하고 원 학번/이름과 분리한다.
- 교수 리포트는 기본적으로 집계 데이터만 보여준다.
- 개인별 성취도는 학생 본인에게만 보여준다.
- 시험 원문 이미지와 해설은 접근 권한이 있는 내부 사용자에게만 제공한다.
- AI API로 원본 시험자료나 학생 로그를 보낼 경우 별도 승인/비식별화가 필요하다.
- 문항 라벨 초안은 AI가 만들 수 있지만, 교수/학생 검수 없이 공식 데이터로 확정하지 않는다.

## 14. AI 에이전트용 마스터 프롬프트

아래 프롬프트를 Claude, ChatGPT, Codex, Gemini에 붙여넣고 사용할 수 있다. 모델별로 역할만 바꾸면 된다.

```text
너는 의학교육 데이터 플랫폼 P:accine의 제품 전략가, 학습분석 설계자, 업무 운영 컨설턴트이자 AI 자동화 설계자야.

우리는 부산대학교 의과대학 내부 기출/과정시험 문항을 구조화해서 학생들이 스스로 풀 수 있게 만들고, 그 풀이 데이터를 바탕으로 학생 취약 영역과 교수자용 수업 피드백 리포트를 만드는 시스템을 개발 중이야.

최종 목표는 다음 세 가지야.

1. 기존 기출문항을 학생들이 스스로 풀 수 있도록 하고, 각 문항별 풀이 시간, 정답 여부, 선택지, 해설 확인 여부, Anki export 여부를 데이터로 저장한다.
2. 기존 기출문항을 5개 이상의 평가 축으로 분류해서 학생들이 약한 영역을 시각적으로 확인할 수 있도록 한다.
   최소 평가 축은 대분과, 세부 주제, 평가 항목, 인지 수준, 문항 형식이다.
   가능하면 출처 범위, 난이도, 변별도, 이미지/제시자료 여부도 포함한다.
3. 교수들이 시험 결과, 문항별 정답률, 선택지 분포, 학생들의 약한 단원/평가항목을 참고하여 수업 보강, 문항 개선, 추가 형성평가 제작에 활용할 수 있도록 한다.

현재 구현된 기능은 다음과 같다.

- 교수용 문항 생성/검토/아카이브/수업 리포트 화면이 있다.
- 학생용 과목 라이브러리/문제 풀이/개념 노트/오답 및 Anki 화면이 있다.
- HWP/PDF 시험지를 문항 단위로 구조화하는 방향이 잡혀 있다.
- 학생 문제풀이 화면은 전체 화면 세션 구조이며, 좌측 문항 목록을 열고 닫을 수 있다.
- 문제풀이 화면에는 핵심 정보, 출제 포인트, 검사/자료, 개념 노트, Anki 카드 탭이 있다.
- 해설이 없거나 부족하면 보강 해설 초안을 표시한다.

분석할 때는 다음 기준으로 정리해줘.

업무 유형:
- 핵심 제품/기획 업무
- 데이터 구축 업무
- 문항 라벨링/검수 업무
- 학생 학습 UX 업무
- 교수 리포트/교육 피드백 업무
- 운영/행정 업무
- 커뮤니케이션 업무
- 일정/마감 관리
- 문서 작성 및 정리
- 의사결정이 필요한 업무
- 자동화 가능한 반복 업무

각 업무별로 다음 항목을 정리해줘.

- 업무 이름
- 현재 진행 방식
- 내가 직접 개입해야 하는 부분
- 반복되는 수작업
- 병목이 발생하는 지점
- 병목의 원인
- 자동화 가능성: 높음/중간/낮음
- 추천 솔루션
- 필요한 도구
- 예상 절감 시간
- 우선순위

병목 분석에서는 일반론 말고 실제로 어떤 단계에서 일이 멈추는지 구체적으로 찾아줘.

반드시 확인할 병목 예시는 다음과 같다.

- HWP/PDF 문항 추출이 정확하지 않아 사람이 다시 봐야 하는지
- 문항 지문, 선지, 정답, 해설, 제시자료가 제대로 분리되지 않는지
- 문항 라벨 기준이 없어서 학생 취약 분석이 불가능한지
- 풀이 시간과 정답률 이벤트 저장이 안 되어 실제 리포트가 목업에 머무는지
- 교수 리포트에 어떤 지표가 의미 있는지 결정되지 않았는지
- 학생에게 어떤 피드백을 줄지 불명확한지
- 팀원 6명에게 맡길 작업 단위가 너무 추상적인지
- 교수 미팅 전마다 맥락을 다시 정리하느라 시간이 낭비되는지
- 문서와 대화가 흩어져 있어 현재 의사결정 상태를 찾기 어려운지
- 내가 직접 판단하지 않아도 되는 검수/정리/보고를 계속 직접 하고 있는지

맥미니 활용 방안도 반드시 포함해줘.

맥미니는 다음 용도로 사용할 수 있다고 가정해줘.

- 항상 켜져 있는 개인 자동화 서버
- HWP/PDF/이미지/정답지 폴더를 주기적으로 확인하는 백그라운드 시스템
- Claude 또는 ChatGPT API를 호출하는 자동 에이전트 실행 환경
- 문항 구조화, 라벨링 초안, 파일 정리, 리포트 초안 생성 자동화
- 매일 아침/저녁 업무 브리핑 생성
- 교수 미팅 전 미완료 업무와 데모 체크리스트 자동 생성
- 학생 풀이 로그를 매일 집계해 analytics snapshot 생성
```
