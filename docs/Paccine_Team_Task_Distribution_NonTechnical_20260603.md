# P:accine 팀원 업무 배분안 - 비전공자용 상세 설명

## 1. 이 프로젝트를 아주 쉽게 설명하면

P:accine은 학교 시험지, 정답지, 해설, 그림 자료를 그냥 파일로 두지 않고, 학생이 풀 수 있고 교수님이 분석할 수 있는 형태로 다시 정리하는 프로젝트입니다.

지금까지는 기출문제나 과정시험 자료가 보통 HWP/PDF 파일 안에 들어 있습니다. 이 상태에서는 학생이 문제를 풀기는 가능하지만, 다음과 같은 일을 하기 어렵습니다.

- 어떤 과목의 어떤 단원이 약한지 자동으로 보기 어렵습니다.
- 어떤 문제에 어떤 그림이 붙어야 하는지 정리하기 어렵습니다.
- 학생이 틀린 문제를 바탕으로 오답노트나 Anki 카드를 만들기 어렵습니다.
- 교수님이 다음 수업에서 무엇을 보강해야 할지 한눈에 보기 어렵습니다.

그래서 이 프로젝트의 핵심은 “AI가 문제를 마구 만들어주는 것”이 아닙니다.

핵심은 다음입니다.

```text
흩어져 있는 시험 자료를
문항 단위로 정리하고
정답, 해설, 그림, 단원, 개념을 연결해서
학생 학습과 교수 피드백에 다시 쓰는 시스템을 만드는 것
```

## 2. 현재까지 만들어진 것

현재 GitHub에는 다음 기능들이 올라가 있습니다.

### 교수 화면에서 가능한 것

- HWP/PDF 시험지를 업로드할 수 있습니다.
- 시험지를 문항 단위로 나눌 수 있습니다.
- 각 문항의 지문, 선지, 정답, 해설을 분리할 수 있습니다.
- 정답지 엑셀 파일을 올리면 정답을 연결할 수 있습니다.
- 문항 검토 화면에서 문제를 확인할 수 있습니다.
- 수업 리포트 화면 목업이 있습니다.

### 학생 화면에서 가능한 것

- 학생이 실제로 문제를 풀 수 있습니다.
- 학습 모드에서는 선지를 고르면 정답과 해설이 바로 보입니다.

## 3. 현재 제일 큰 문제

현재 가장 큰 문제는 크게 세 가지입니다.

### 문제 1. 그림이 있는 문제에서 실제 이미지가 안 붙는 경우가 있음

예를 들어 문제 화면에 이렇게 보이는 경우가 있습니다.

```text
Q7. 다음 중 이 환자에서 침범되지 않았을 것으로 판단되는 해부학적 구조물은?

<그림>

① ...
② ...
③ ...
```

여기서 `<그림>`이라고 표시되지만, 실제 그림 파일이 화면에 뜨지 않는 경우가 있습니다.

이유는 간단히 말하면 다음과 같습니다.

```text
시험지 안에서 그림 파일은 추출됐지만,
그 그림이 몇 번 문제에 붙어야 하는지
자동으로 100% 알기 어려운 경우가 있기 때문입니다.
```

그래서 사람이 해야 할 일이 있습니다.

```text
그림 파일들을 직접 확인하고
이 그림은 몇 번 문제에 붙어야 하는지
표로 정리해주는 작업
```

### 문제 2. 문제는 풀 수 있지만, 아직 단원/개념 분류가 부족함

학생이 문제를 풀었을 때 “틀렸습니다”만 보여주면 별로 도움이 안 됩니다.

좋은 피드백은 이런 식이어야 합니다.

```text
이 문제는 신경및특수감각기학 중 말초신경 단원입니다.
평가 항목은 병변 위치 추론입니다.
정중신경/척골신경 감별을 다시 복습하는 것이 좋습니다.
비슷한 문제 3개를 더 풀어보세요.
```

이렇게 하려면 각 문제마다 다음 정보가 붙어 있어야 합니다.

- 과목
- 세부 단원
- 평가 항목
- 핵심 개념
- 문제 유형

이 작업은 의학적 판단이 필요해서 의대생 팀원이 해주는 것이 좋습니다.

### 문제 3. UI가 아직 실제 서비스처럼 세밀하지 않음

현재 화면은 기본 기능을 보여주는 수준입니다.

팀원들이 와이어프레임을 그려오면 구현도를 크게 올릴 수 있습니다.

와이어프레임은 예쁜 디자인이 아니어도 됩니다.

손그림이어도 됩니다.

중요한 것은 다음입니다.

```text
사용자가 이 화면에서 무엇을 하려고 하는지
어떤 버튼이 어디에 있어야 하는지
어떤 정보가 먼저 보여야 하는지
다음 화면으로 어떻게 넘어가야 하는지
```

## 4. 용어 설명

팀원들이 헷갈릴 수 있는 용어를 쉽게 정리합니다.

### 문항

시험 문제 하나를 뜻합니다.

예:

```text
7. 다음 중 이 환자에서 침범되지 않았을 것으로 판단되는 해부학적 구조물은?
```

### 지문

문제에서 물어보는 문장입니다.

예:

```text
다음 중 이 환자에서 침범되지 않았을 것으로 판단되는 해부학적 구조물은?
```

### 선지

객관식 보기입니다.

예:

```text
① 피질연수로
② 설하신경
③ 전각세포
④ 피질척수로
⑤ 적핵척수로
```

### 제시자료

문제를 풀 때 참고해야 하는 추가 자료입니다.

예:

- 증례 설명
- 표
- 그래프
- X-ray
- CT
- MRI
- 병리 사진
- 심전도
- 해부 그림

### 해설

정답이 왜 맞고 다른 선지가 왜 틀렸는지 설명하는 부분입니다.

### 라벨

문제에 붙이는 분류 이름입니다.

예:

```text
과목: 신경및특수감각기학
세부 단원: 말초신경
평가 항목: 병변 위치 추론
핵심 개념: 척골신경, 정중신경
```

### DB

데이터베이스의 줄임말입니다.

어렵게 생각하지 않아도 됩니다.

여기서는 그냥 “잘 정리된 표와 파일 묶음”이라고 생각하면 됩니다.

### media asset

문제에 들어가는 그림, 사진, 영상, 표 같은 자료입니다.

쉽게 말하면 “문제용 이미지 파일”입니다.

### media_refs

문제와 이미지 파일을 연결해주는 표시입니다.

쉽게 말하면 다음과 같습니다.

```text
7번 문제에는 BIN0001.bmp 그림을 붙인다.
9번 문제에는 BIN0003.bmp 그림을 붙인다.
```

### 와이어프레임

화면 설계도입니다.

예쁜 디자인이 아니라, 버튼과 정보가 어디에 있을지 그린 초안입니다.

손그림, PPT, Figma, Canva, 아이패드 스케치 모두 가능합니다.

### 검수

AI나 프로그램이 자동으로 정리한 결과가 맞는지 사람이 확인하는 일입니다.

## 5. 팀원 전체가 지켜야 할 원칙

### 원칙 1. 완벽한 결과보다 발견한 문제를 적는 것이 중요함

처음부터 완벽하게 정리하려고 하면 시간이 오래 걸립니다.

이번 주에는 다음을 찾는 것이 더 중요합니다.

- 어디가 잘못 추출됐는지
- 어떤 화면이 불편한지
- 어떤 정보가 빠져 있는지
- 어떤 작업은 사람이 해야 하는지

### 원칙 2. 어려운 표현보다 실제 예시를 적기

좋지 않은 예:

```text
학생 피드백 UX가 부족함.
```

좋은 예:

```text
학생이 7번 문제를 틀렸을 때, 단순히 정답만 보여주면 부족합니다.
이 문제는 해부학적 구조물 감별 문제이므로,
관련 개념 버튼을 누르면 피질척수로/피질연수로 차이를 보여주면 좋겠습니다.
```

### 원칙 3. 화면을 그릴 때는 사용자의 입장에서 생각하기

교수님 입장:

- 지금 당장 검토해야 할 문제는 무엇인가?
- 학생들이 많이 틀린 단원은 무엇인가?
- 다음 수업에서 무엇을 보강해야 하는가?

학생 입장:

- 오늘 무엇을 풀어야 하는가?
- 내가 왜 틀렸는가?
- 다음에 무엇을 복습해야 하는가?
- 비슷한 문제를 더 풀 수 있는가?

## 6. 의대생 3명 업무

의대생 팀원들은 의학적 판단과 학생 입장에서의 사용성을 봐주면 됩니다.

코딩을 할 필요는 없습니다.

### 의대생 1. 문항 구조 검수 담당

#### 한 줄 역할

자동으로 정리된 문제가 실제 시험지와 맞게 나뉘었는지 확인하는 역할입니다.

#### 왜 필요한가

프로그램이 HWP/PDF에서 문제를 자동으로 나눠도 가끔 실수합니다.

예를 들어 다음 문제가 생길 수 있습니다.

- 7번 문제가 빠짐
- 8번 문제가 7번에 붙어버림
- 5번 선지 뒤에 해설이 붙어버림
- 정답 표시가 잘못 들어감
- `<그림>`만 있고 실제 그림이 없음

이런 문제를 사람이 찾아줘야 프로그램을 고칠 수 있습니다.

#### 보면 되는 것

- 학생 문제풀이 화면
- 교수 검수 미리보기 화면
- Markdown 검수본

#### 해야 할 일

1. 신경및특수감각기학 2차 문제 중 Q1~Q30을 먼저 봅니다.
2. 각 문제가 정상적으로 나뉘었는지 확인합니다.
3. 지문, 선지, 정답, 해설이 이상한 문항을 표시합니다.
4. 그림이 있어야 하는데 안 뜨는 문항을 표시합니다.
5. 학생에게 바로 공개해도 될 문항과 검수 필요한 문항을 나눕니다.

#### 제출물

`문항 구조 검수표`

표 양식:

| 과목 | 시험 | 문항 번호 | 확인 결과 | 문제점 | 수정 제안 |
| --- | --- | ---: | --- | --- | --- |
| 신경및특수감각기학 | 2차 | 7 | 검수 필요 | 그림이 안 뜸 | 이미지 후보를 찾아 연결 |
| 신경및특수감각기학 | 2차 | 9 | 정상 | 없음 | 공개 가능 |

#### 좋은 코멘트 예시

```text
Q7은 문제 지문과 선지는 잘 나뉘었지만, 제시자료가 <그림>으로만 표시되고 실제 이미지가 없습니다.
학생 풀이용으로 공개하려면 이미지 연결이 먼저 필요합니다.
```

### 의대생 2. 단원/개념 라벨링 담당

#### 한 줄 역할

각 문제가 어떤 과목, 어떤 단원, 어떤 개념을 묻는지 분류하는 역할입니다.

#### 왜 필요한가

학생이 문제를 풀고 나서 단순히 “맞음/틀림”만 보면 도움이 적습니다.

우리가 원하는 피드백은 다음과 같습니다.

```text
너는 신경및특수감각기학 중 말초신경 문제에서 약하다.
특히 병변 위치 추론 문제를 많이 틀렸다.
정중신경, 척골신경 감별을 복습해라.
```

이런 피드백을 만들려면 문항마다 라벨이 있어야 합니다.

#### 해야 할 일

1. 신경및특수감각기학의 큰 단원 목록을 만듭니다.
2. 각 단원 안에 세부 주제를 정리합니다.
3. 문항 30~50개에 직접 라벨을 붙입니다.
4. 라벨 기준이 애매한 문항은 따로 표시합니다.

#### 라벨 예시

```text
과목: 신경및특수감각기학
세부 주제: 말초신경
평가 항목: 병변 위치 추론
핵심 개념: 척골신경, 정중신경, 감각저하
```

#### 평가 항목 후보

- 병태생리
- 역학/위험인자
- 임상양상
- 진단기준
- 검사 선택
- 검사 해석
- 감별진단
- 치료 선택
- 초기 처치
- 합병증/예후
- 예방/공중보건
- 법/윤리/제도
- 환자 설명/의사소통

#### 제출물

`문항 라벨링 표`

표 양식:

| 문항 번호 | 과목 | 세부 주제 | 평가 항목 | 핵심 개념 | 애매한 점 |
| ---: | --- | --- | --- | --- | --- |
| 7 | 신경및특수감각기학 | 뇌간/운동로 | 해부 구조 감별 | 피질척수로, 피질연수로 | 이미지 필요 |
| 9 | 신경및특수감각기학 | 말초신경 | 병변 위치 추론 | 척골신경 | 없음 |

### 의대생 3. 학생 UX/피드백 담당

#### 한 줄 역할

학생이 문제를 풀고 복습하는 화면이 어떻게 생기면 좋을지 설계하는 역할입니다.

#### 왜 필요한가

기능이 있어도 화면이 불편하면 학생은 쓰지 않습니다.

학생에게 필요한 것은 다음입니다.

- 오늘 무엇을 풀지
- 내가 왜 틀렸는지
- 관련 개념은 무엇인지
- 비슷한 문제를 더 풀 수 있는지
- Anki 카드로 저장할 수 있는지

#### 해야 할 일

1. 학생 문제풀이 화면을 그립니다.
2. 정답/해설 화면을 그립니다.
3. 오답노트 화면을 그립니다.
4. 관련 개념/관련 문제 추천 화면을 그립니다.
5. 학생에게 보여줄 피드백 문구 예시를 작성합니다.

#### 와이어프레임에 포함할 것

- 과목 선택
- 시험 세트 선택
- 학습 모드/시험 모드 선택
- 문제 본문
- 그림 자료 위치
- 선지
- 정답 확인
- 해설
- 관련 개념 버튼
- 비슷한 문제 추천
- Anki 카드 만들기 버튼

#### 제출물

- 학생 문제풀이 화면 와이어프레임
- 오답노트 화면 와이어프레임
- 피드백 문구 20개
- Anki 카드 예시 10개

#### 피드백 문구 예시

```text
이 문제는 단순 암기보다 해부학적 구조를 구분하는 문제입니다.
정답을 맞히려면 피질척수로와 피질연수로의 차이를 알아야 합니다.
관련 개념을 먼저 확인한 뒤 비슷한 병변 위치 추론 문제를 3개 더 풀어보세요.
```

## 7. 의생공 신입생 2명 업무

의생공 신입생 팀원들은 의학적 판단을 깊게 하기보다, 자료 정리와 화면 설계를 도와주면 됩니다.

### 의생공 신입생 1. 이미지/제시자료 정리 담당

#### 한 줄 역할

문제에 들어가야 하는 그림 파일을 찾아서 몇 번 문제에 붙을지 정리하는 역할입니다.

#### 왜 필요한가

현재 일부 문제에서 `<그림>`이라고만 나오고 실제 그림이 안 보입니다.

이 문제를 해결하려면 사람이 그림 파일을 직접 확인해서 연결표를 만들어야 합니다.

#### 쉽게 비유하면

문제는 “문제 카드”입니다.

이미지는 “사진첩에 들어 있는 사진”입니다.

해야 할 일은 다음입니다.

```text
7번 문제 카드에는 사진첩의 BIN0001.bmp를 붙인다.
9번 문제 카드에는 사진첩의 BIN0003.bmp를 붙인다.
```

이런 식으로 연결표를 만드는 것입니다.

#### 현재 이미지 파일 위치

```text
data_private/course_exams/media/과목_시험명/BIN0001.bmp
data_private/course_exams/media/과목_시험명/BIN0002.bmp
...
```

#### 해야 할 일

1. 이미지 파일을 하나씩 열어봅니다.
2. 해당 이미지가 어떤 문제에 필요한지 찾습니다.
3. 이미지 종류를 적습니다.
4. 확실한지 애매한지 표시합니다.
5. 환자 정보가 보이는지 확인합니다.

#### 이미지 종류 후보

- X-ray
- CT
- MRI
- 초음파
- ECG
- EEG
- 병리
- 임상 사진
- 해부 그림
- 표
- 그래프
- 기타

#### 제출물

`이미지 연결표`

표 양식:

| 과목 | 시험 | 문항 번호 | 현재 화면 | 연결할 이미지 파일 | 이미지 종류 | 확신도 | 비고 |
| --- | --- | ---: | --- | --- | --- | ---: | --- |
| 신경및특수감각기학 | 2차 | 7 | `<그림>` | BIN0001.bmp | 해부 그림 | 70% | 사람 확인 필요 |
| 신경및특수감각기학 | 2차 | 9 | 이미지 있음 | BIN0003.bmp | 해부 그림 | 100% | 정상 |

#### 주의할 점

진단명을 확정하려고 하지 않아도 됩니다.

처음에는 아래 정도만 해도 충분합니다.

```text
이 이미지는 X-ray인지, CT인지, 해부 그림인지
몇 번 문제와 관련 있어 보이는지
확실한지 애매한지
```

### 의생공 신입생 2. UI 참고자료/와이어프레임 담당

#### 한 줄 역할

다른 학습 서비스 화면을 참고해서 우리 서비스 화면을 어떻게 바꾸면 좋을지 제안하는 역할입니다.

#### 왜 필요한가

현재 UI는 기능 중심으로 만들어져 있어서 다소 딱딱합니다.

학생이나 교수님이 실제로 쓰고 싶게 만들려면 화면 흐름을 다듬어야 합니다.

#### 참고하면 좋은 서비스

- AMBOSS
- 알렌의 서재
- UWorld
- Osmosis
- Anki
- 학교 iMedSIS

#### 해야 할 일

1. 참고 서비스 화면을 캡처합니다.
2. 좋은 점과 불편한 점을 적습니다.
3. 우리 서비스에 적용하면 좋을 화면 구조를 그립니다.
4. 학생 화면과 교수 화면을 각각 나눠서 제안합니다.

#### 반드시 그려볼 화면

- 학생 과목 서재
- 학생 문제풀이
- 정답/해설 확인
- 오답 복습
- 교수 문항 검토
- 교수 수업 리포트
- 이미지 자료 검수 화면

#### 제출물

- UI 참고자료 모음
- 학생 화면 와이어프레임
- 교수 화면 와이어프레임
- UI 개선 아이디어 10개

#### 좋은 제안 예시

```text
학생 문제풀이 화면에서는 문제와 선지가 너무 아래로 길게 늘어지면 피로합니다.
왼쪽에는 문제, 오른쪽에는 힌트/개념/오답 기록을 두면 좋겠습니다.
이미지 문항은 이미지를 먼저 크게 보여주고, 클릭하면 확대되게 하면 좋겠습니다.
```

## 8. 석사 팀원 업무

석사 팀원은 기술 구조와 AI 활용 방식을 정리해주면 좋습니다.

단, 너무 복잡한 구현을 바로 하지 않아도 됩니다.

이번 주 목표는 “어떤 정보를 어떤 구조로 저장하면 좋을지”를 설계하는 것입니다.

### 석사. 데이터 구조/AI 파이프라인 담당

#### 한 줄 역할

문제, 정답, 해설, 이미지, 학생 풀이 기록을 어떤 구조로 저장할지 설계하는 역할입니다.

#### 왜 필요한가

지금은 로컬 파일로 저장하고 있지만, 나중에는 서버와 데이터베이스에 올려야 합니다.

그러려면 정보 구조가 미리 정리되어 있어야 합니다.

#### 쉽게 설명하면

우리가 저장해야 하는 것은 다음입니다.

```text
어떤 과목의 어떤 시험인지
몇 번 문제인지
문제 지문은 무엇인지
선지는 무엇인지
정답은 무엇인지
해설은 무엇인지
그림은 어떤 파일인지
학생이 어떤 답을 골랐는지
그 학생이 어떤 단원에서 약한지
```

#### 해야 할 일

1. 저장해야 할 정보 목록을 정리합니다.
2. 각 정보가 서로 어떻게 연결되는지 그림으로 그립니다.
3. AI가 자동으로 해도 되는 일과 사람이 확인해야 하는 일을 나눕니다.
4. 이미지 연결이 안 되는 문제를 어떻게 해결할지 구조를 제안합니다.
5. 학생 풀이 기록을 나중에 어떻게 저장하면 좋을지 제안합니다.

#### 저장 구조 예시

```text
과목
  -> 시험
    -> 문항
      -> 선지
      -> 정답
      -> 해설
      -> 이미지
      -> 라벨
      -> 학생 풀이 기록
```

#### AI가 해도 되는 일

- 문항을 대략적으로 분류하기
- 이미지 종류를 대략적으로 추정하기
- 학생 오답 패턴을 요약하기
- Anki 카드 초안을 만들기
- 교수 리포트 문장 초안을 만들기

#### 사람이 꼭 확인해야 하는 일

- 정답이 맞는지
- 해설이 맞는지
- 이미지가 올바른 문제에 붙었는지
- 학생에게 공개해도 되는 자료인지
- 환자 정보가 노출되지 않는지
- 문항 라벨이 실제 강의 단원과 맞는지

#### 제출물

- 데이터 구조 그림
- 저장해야 할 정보 목록
- AI 자동화 가능/불가능 구분표
- 이미지 연결 문제 해결 아이디어
- 서버에 올리기 전 체크리스트

## 9. 이번 주 우선순위

### 1순위. 신경및특수감각기학 2차 데모 완성도 올리기

이 자료가 현재 가장 데모에 좋습니다.

이유:

- 문항 수가 많습니다.
- 정답이 대부분 연결되어 있습니다.
- 이미지 문항도 많습니다.
- 학생 문제풀이 화면에서 실제로 풀 수 있습니다.

이번 주에는 이 자료를 중심으로 보면 됩니다.

해야 할 일:

- Q1~Q30 문항 구조 확인
- Q7처럼 이미지가 안 뜨는 문항 확인
- 이미지 파일과 문항 연결표 작성
- 문항 30~50개 라벨링
- 학생 풀이 화면 개선안 작성

### 2순위. 이미지 연결 문제 해결

현재 가장 눈에 띄는 문제입니다.

학생이 이미지 문항을 풀 때 `<그림>`만 보이면 서비스 완성도가 크게 떨어집니다.

팀원들이 이미지 연결표를 만들어오면 Codex가 그 표를 읽어서 실제 화면에 이미지를 붙이는 기능을 만들 수 있습니다.

### 3순위. 교수님 미팅용 데모 흐름 만들기

교수님께 보여줄 때는 기술 설명보다 아래 흐름이 좋습니다.

```text
1. 학교 시험지를 올립니다.
2. 문제가 자동으로 나뉩니다.
3. 학생이 문제를 풀 수 있습니다.
4. 이미지가 필요한 문항은 이미지 DB와 연결합니다.
5. 문항에 단원/평가항목 라벨을 붙입니다.
6. 학생 풀이 결과를 바탕으로 교수님께 보강 포인트를 보여줍니다.
```

## 10. 팀원들이 제출하면 좋은 공통 양식

모든 팀원은 매주 아래 4줄만 적어도 됩니다.

```text
1. 내가 본 화면/자료:
2. 발견한 문제:
3. 제안하는 개선:
4. Codex/Claude에게 맡기고 싶은 일:
```

예시:

```text
1. 내가 본 화면/자료:
신경및특수감각기학 2차 Q1~Q10 학생 문제풀이 화면

2. 발견한 문제:
Q7에서 <그림>만 보이고 실제 그림이 뜨지 않음.
Q8은 이미지가 필요 없어 보이는데 image_interpretation으로 표시됨.

3. 제안하는 개선:
이미지 있는 문제만 따로 모아서 검수하는 화면이 필요함.

4. Codex/Claude에게 맡기고 싶은 일:
이미지 파일을 선택해서 문항에 연결하는 UI를 만들어주면 좋겠음.
```

## 11. 팀원에게 보낼 메시지 초안

```text
안녕하세요! P:accine 프로젝트 작업을 역할별로 나눠서 진행하려고 합니다.

현재 사이트에는 HWP/PDF 시험지를 문항 단위로 나누고, 학생이 일부 세트를 직접 풀 수 있는 MVP까지 구현되어 있습니다.

다만 자동화만으로는 한계가 있어서, 각자 한 파트를 맡아 사람이 봐야 하는 부분을 정리해주시면 좋겠습니다.

코딩을 하실 필요는 없고, 완성도 높은 디자인을 만들어오실 필요도 없습니다.

각자 맡은 화면이나 자료를 보고
“어디가 이상한지”
“어떤 정보가 빠졌는지”
“어떻게 바꾸면 실제로 쓰기 편할지”
를 정리해주시면 됩니다.

이번 주 공통 제출 형식은 아래 4줄입니다.

1. 내가 본 화면/자료:
2. 발견한 문제:
3. 제안하는 개선:
4. Codex/Claude에게 맡기고 싶은 일:

의대생 팀원분들은 문항 구조, 정답/해설, 단원 라벨, 학생 피드백 쪽을 봐주시면 좋고,
의생공 팀원분들은 이미지 자료 정리, UI 레퍼런스, 와이어프레임 쪽을 봐주시면 좋겠습니다.
석사 팀원분께는 데이터 구조와 AI 활용 흐름을 같이 봐주십사 부탁드리려 합니다.

부담 갖지 말고, 각자 맡은 부분에서 “실제로 쓰기 좋게 만들려면 무엇이 필요할지”를 편하게 정리해주시면 됩니다.
```
